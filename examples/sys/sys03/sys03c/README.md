# SYS-03C：可调发送周期的跨核 Queue IPC 测试

默认发送周期为 1000 µs。通过 `idf.py --preview menuconfig` 修改：

`SYS-03C IPC benchmark -> TX message period (us)`

建议测试序列：1000、500、200、100、50、20、10、5、0 µs。每个配置烧录后等待至少 5 秒，记录 TX/RX 日志。

主要判断指标：

- `TX rate`：发送成功速率，理想值约为 `1,000,000 / period` msg/s；
- `drop_rate`：发送时队列已满导致的丢消息比例；
- `gaps`：接收端根据序号发现的消息间隙；
- `queue_max`：测试窗口内队列最大深度；
- `latency_avg/max`：跨核消息平均和最大延迟。

当发送周期继续缩短时，若出现 `drop_rate > 0`、`gaps > 0`、队列深度长期接近队列长度，或吞吐量不再随设定速率增加，即可认为达到当前接收任务/队列配置的性能拐点。

`period=0` 表示尽可能高速发送，用于测量极限吞吐；该模式会明显提高发送核负载。

如果使用 1 ms 以下周期或 `period=0`，发送任务会持续占用发送核。该 demo 已关闭 CPU0 空闲任务看门狗检查，避免把“人为满载”误判为 IPC 故障；系统任务看门狗仍可用于发现真正的任务卡死。每次修改源码或 Kconfig 后必须重新 `reconfigure`、编译并烧录，不能只打开旧的 `build\sys03c.bin`。

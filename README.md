# ESP32-S31 · SYS-02 并行基线性能测试 —— 结论汇总

---

## 一、内存与系统性能

### 1. 单任务内存带宽
| 方向 | 32 KiB | 64 KiB | 128 KiB |
|---|---|---|---|
| 片上内存读写 | 496.07 | 496.71 | 497.14 MiB/s |
| 片上 → PSRAM | 495.99 | 490.49 | 98.32 MiB/s |
| PSRAM → 片上 | 496.22 | 491.73 | 112.78 MiB/s |
| PSRAM 读写 | 482.41 | 53.36 | 53.41 MiB/s |

**结论**
- 片上内存读写稳定在约 **497 MiB/s**，不随缓冲区增大劣化。
- PSRAM 读写从 64 KiB 起骤降约 **89%**（482.4 → 53.4 MiB/s）；片上↔PSRAM 跨片搬运在 128 KiB 也跌至 ~98/113 MiB/s。
- 根因是 **Cache 容量**：CPU 参与 PSRAM 访问时依赖 Cache，块大小超过 Cache 可缓存范围后命中率崩塌，APB/缓存一致性开销成为瓶颈。

**工程建议**
- 大数据块 PSRAM 搬运不要全部走 CPU 拷贝，优先走 **DMA**；确需 CPU memcpy 时，把块切到 ≤ Cache 容量（约 64 KiB 以内）分批拷贝。

### 2. 双核并行访问（SYS-02D）
| 场景 | 结果 |
|---|---|
| D1 Core1 PSRAM 读写（Flash 并行） | 28.9 → 3.9 MiB/s，**SPI 总线 + Cache 竞争**，带宽明显下降 |
| D2 双核同时片上读写 | 双核各 ~495–497 MiB/s，**共享 SRAM 几乎无影响**（128 KiB 时资源分配失败） |
| D3 双核同时 PSRAM 读写 | 每核 ~31.4 MiB/s，合计 ~62.8 MiB/s，**PSRAM 共享带宽被均分** |
| D4 PSRAM + 片上混合 | PSRAM 大块 481.9 → 53.4 MiB/s，片上保持 ~497 MiB/s，**两条链路相对独立** |
| D5 双核同时写 PSRAM | 32 KiB 近高速，64 KiB 后 ~49.2 MiB/s/核，受 **PSRAM 写带宽**限制 |

**结论**：双核并行访问时，瓶颈集中在 **PSRAM 控制器共享带宽 / SPI 总线竞争**；

### 3. 长时间内存压测（SYS-02A）
- 加压至 **14.37 h**，内部 RAM free=454,759（最大连续块 376,832）、PSRAM free=16,250,336（最大连续块 15,990,784），各采样点全程**零变化**。
- **结论**：长时间运行无内存泄漏、无碎片化，静态余量充足。

### 4. GPTimer 中断（SYS-03B）
| 频率 | 抖动峰峰值 |
|---|---|
| 1 k–20 kHz | 0 µs（1 µs 时间戳分辨率下） |
| 50 kHz | 2 µs |
| 100 kHz | 13 µs（周期波动 5–18 µs） |

- 1 k–100 kHz 实测频率均与设定一致，**未丢中断**；100 kHz 仍能维持平均 10 µs 周期，但实时性裕量明显下降。
- **判定**：50 kHz 以上视为高压场景；空载基线未覆盖 Wi-Fi、Flash/PSRAM、高 CPU 负载，实际项目需按组合场景复测。

### 5. 双核间 IPC 通信（SYS-03C）
| 周期 | 接收延迟 | 错误率 |
|---|---|---|
| 200 µs 及以上 | ~12–13 µs | 0（稳定区间） |
| 100 µs | 12.9 µs | 0.0001（**首错点**） |
| 50 µs | 11.45 µs | 0.00073（队列饱和） |

**结论**：IPC 队列在 **200 µs 以上完全稳定**；单核发送速率建议 ≥ 200 µs/包，避免 100 µs 以下的高频压测场景。

## 二、音频链路（ES8389 · I2S · APLL MCLK）

### 6. IIS 链路测试
**BLOCK_FRAMES 压力扫描（固定 48 kHz）**
- BLOCK_FRAMES=1（块时长 0.02 ms）：实测 ~24 kHz，**失真且触发看门狗**；
- =2（0.04 ms）：临界，速率掉到 46.4 kHz 且 WDT 触发；
- **≥4（块时长 ≥ 0.083 ms）：实测稳定 48 kHz，无 WDT、无读写错误。**

**固定 10 ms 块时长、采样率扫描**
| 采样率 | 实测 | 吞吐 | app_cpu | 结果 |
|---|---|---|---|---|
| 16 k / 32 k / 44.1 k / 48 k | 匹配 | 62.5–187.6 KiB/s | ≤ 0.57 | **Pass** |
| 88.2 k / 96 k | 匹配 | 344.6 / 375 KiB/s | 1.04 / 1.15 | **Pass** |
| 192 k | 未运行 | — | — | **Fail**：MCLK=384 倍频下 APLL 超上限 |

**结论与建议**
- 16–96 kHz 全程无读写错误，96 kHz 时 app_cpu 仅 ~1.15%，**IIS 数据交互不是 CPU 瓶颈**。
- 192 kHz 失败原因是**时钟生成能力**（APLL 上限）而非 Codec 标称采样率；建议按目标采样率**动态选择 MCLK 倍频**，并用示波器验证 WS/BCLK。

### 7. 录音连续性测试
- 48 k / 88.2 k / 96 k（BLOCK_FRAMES=480，增益 20 dB，30 s）：失败次数 **0**、削波 **0**。
- 48 kHz 下 BLOCK_FRAMES=16–1024：全部 **0 失败**。
- **结论**：办公室环境下录音连续性好，嘈杂环境偶发削波但**始终无读取错误**，得益于 IIS 通路性能；12 h 加压数据**待补充**。

### 8. 播放持续性测试
- BLOCK_FRAMES=16–1024（1 kHz 正弦波、48 kHz）：播放失败次数**全部为 0**，实测采样率稳定在约 48 kHz。
- **结论**：播放链路可持续，`esp_codec_dev_write` 无任何失败。

### 9. 音频链路全双工测试（边录边放）
- Core0 播放 + Core1 录音，BLOCK_FRAMES=16–1024：rx/tx 均稳定在约 48 kHz 附近，**rx_err/tx_err 全 0**。
- **结论**：全双工“边录边放”在不同块时长下均稳定；

## 三、LCD 显示

### 10. LCD PCLK 上限
- **纯硬件链路**：18–50 MHz 全部正常，**56 MHz 黑屏**，纯硬件稳定上限约 **50 MHz**。
- **LVGL 全屏刷新压力**（16 bit 单缓冲、40 区块、16 ms 刷新）：18–50 MHz **均出现短暂横条**，提高 PCLK 改善有限。
- **瓶颈**：PSRAM→PSRAM 数据拷贝 + LVGL 全屏软件渲染耗时过长，单缓冲下读写重叠。
- **建议**：启用双缓冲并优化刷新策略；产品中避免连续高负载全屏刷新。

### 11. LCD 缓冲策略对比（800×480 RGB565、PCLK 18 MHz、LVGL 16 ms）
| 方案 | 关键数据 | 结论 |
|---|---|---|
| 单帧 + Partial（内部 RAM） | 40 行：avg_flush 3.7 ms / 339.4；80 行：7.1 ms / 174；**240 行分配失败** | 40–80 行为实际可行区间；行数↑ → flush 时间线性↑、内存线性↑，撕裂风险不消除 |
| 单帧 + Partial（Draw Buffer 在 PSRAM） | — | **触发看门狗复位**：PSRAM→PSRAM 带宽低，喂狗不及时 |
| 单帧 + Partial + DRAW_BUF_DOUBLE=y | 40 行：3.7 ms / 342.5；80 行：7.1 ms / 177 | 与双 buffer=n 几乎一致，**无明显吞吐收益**且内存翻倍 |
| 双帧 + LVGL Direct | 18 / 24 MHz 均 **29 fps**，撕裂明显改善，占用 ~1.5 MB PSRAM | 画面完整性最好；提高 PCLK 无帧率收益（受 LVGL 整帧渲染 / PSRAM 带宽限制） |

**选型建议**：资源优先 → `Single + Partial`、内部 DMA RAM、40–80 行起步；画面完整性优先 → `Double + Direct`；`DRAW_BUF_DOUBLE` 仅作有条件的流水线实验项。

### 12. LVGL 负载（基线 800×480、PCLK 18 MHz、双缓冲、16 ms）
- 控件 **4–16 个 → 约 29 fps 稳定**；**32 个起降至 13–18 fps**，32 为性能拐点。
- 控件增加时 CPU 负载变化不大：瓶颈在 LVGL 渲染、失效区域管理与内存访问效率，而非 CPU。
- 刷新频率 ≥ 31 Hz 后帧率仍约 28 fps，**继续提高刷新频率无收益**。
- **建议**：常用刷新周期取 **16–32 ms**，控制同屏活动控件数量，避免频繁全屏刷新；30 fps 是 400×800 屏 LVGL 场景下的主要瓶颈。

### 13. 长文本滚动测试（歌词滚动）
- 滚动速度等级 4–64、文本长度 1800–4096：全程 **29.4 fps**、无卡顿、无中文占位符，heap/PSRAM 余量恒定。
- **结论**：生成长文本滚动无性能拐点，**不是 ESP32-S31 的渲染性能瓶颈**，长时间运行无内存减少。

### 14. LCD 图像测试（缩放 / 旋转）
- **缩放**（双缓冲、PCLK 18 MHz、开启重解码）：96×96 及其下各尺寸解码耗时约 **5.1–6.7 ms（固定开销）**，FPS 28.8–29.5，无解码错误；缩放解码对整体帧率影响不大。
- **旋转**：225–1800 °/s 时帧率基本不变（~29.4 fps），旋转不增加渲染负载；28.8° 步长（1800 °/s）时**略有卡顿**。
- **结论**：小图缩放/旋转无性能瓶颈；解码器“启用缩放”存在固定开销，解大图/连续重解码场景需另行评估。

## 四、触摸（GT1151）

### 15. 触摸精度测试（9 点 × 3 轮）
- 中心点误差约 **4–10 px**，边缘点（四角/边）约 **20–30 px**（最大 37.8 px）；个别样本存在采样失败（第 2 轮中心点 16 次）。
- **结论**：GT1151 I2C 通信与连续采样总体稳定，但**未经校准**时边缘误差较大；可满足普通按钮与界面交互，**不适合高精度触控**。
- **建议**：进行四点/九点坐标校准；统计时剔除触摸切换阶段的异常样本。

### 16. 触摸并发性能测试（UI 刷屏 + PSRAM 负载 + 音频播放）
| CPU 负载 | LVGL 响应触摸 | 端到端延迟 |
|---|---|---|
| 0.1–0.4 | 2.6–3.1 ms | 15.9–19.9 ms |
| 0.6 | 7.0 ms | 18.1 ms |
| 0.9 | 9.0 ms | 9.6 ms |

- **40% CPU 负载下工作最佳；40%–60% 之间存在主要性能拐点**（触摸响应延时约 7 ms 起）。
- ESP32-S31 满载场景下端到端触摸延迟**中位数 10–20 ms，99% 场景低于 37 ms**，满足产品触摸交互响应要求。

**工程建议**：产品设计中长期 CPU 占用建议控制在 **60% 以下**；高负载场景优先保证刷屏任务的调度，必要时降低 PSRAM 搬运任务的优先级。
